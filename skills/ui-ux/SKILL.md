# 界面设计与用户体验规范

> 本文件为项目开发工作流的阶段 04 规范。智能体在 PRD 确认后必须执行本规范，依据业务功能与体验准则在项目根目录生成 DESIGN.md 实体设计方案。

---

## 一、阶段定位与界面设计核心红线

智能体在推演设计时，必须严格遵守以下硬性禁止红线，坚决剔除一切廉价的生成式页面质感：

1. 严禁使用绘文字充当图标：坚决禁止使用任何 Emoji 字符作为页面按钮、导航菜单或状态指示图标；必须严格选用项目既定组件库内置的矢量 Icon 组件，如 Lucide、Heroicons 或框架专用图标库。
2. 严禁标题附带任何副标题与说明文案：坚决禁止在标题下方添加任何形式的副标题、英文翻印或补充解释说明文字；模块标题必须干脆利落，功能边界完全依靠清晰的版面结构与控件自明，杜绝任何形式的文字打补丁与视觉噪音。
3. 严禁左右对称对半分栏：视图严禁采用刻板生硬的左右各占一半对半分栏布局，避免视觉割裂与呆滞感。
4. 强制采用自然上下流式布局：页面主体骨架必须采用清晰的主次自上而下递进布局，引导视觉重心单向自然流动。
5. 严禁页面元素堆砌，保证充足留白：坚决杜绝信息密不透风的视觉拥挤；必须通过大面积克制留白与合理行距拉开呼吸感，以空间间隔划分内容层级，而非依赖密集的边框与杂乱卡片。
6. 严禁使用荧光与外发光特效：坚决杜绝刺眼的荧光绿、荧光粉、霓虹发光色以及任何元素边缘外发光阴影特效，彻底摒弃劣质廉价的科技感渲染。
7. 原型实体归档与防上下文膨胀原则：根目录的 DESIGN.md 与归档于 docs/stitch 目录下的原型文件同为本阶段的必须交付物；生成原型的手段则保持灵活，配置 Stitch MCP 服务为可选推荐方式，若未配置 MCP，可直接引导用户访问 https://stitch.withgoogle.com 生成后将原型产物存放至 docs/stitch 目录；同时坚决禁止将庞大的原型代码与冗余数据直接完整注入当前会话，严防智能体上下文过载。

## 二、设计系统基础资产与色彩规划

智能体在构建根目录 DESIGN.md 时，确立全局令牌体系：

### 1. 颜色体系与操作高亮规划
- 色彩基调：以素雅、沉稳、耐看的低饱和度中性色作为全站视觉底座。
- 饱和度控制：除核心警示与核心主操作外，全站优先选择饱和度较低、对比温和舒适的色彩，杜绝高饱和度大色块造成的视觉疲劳。
- 中性色阶梯：建立从深色正文文字、次级说明文字、浅灰细分割线到极浅背景底色的严密中性色带。
- 主要操作高亮突显：主要功能的操作按钮必须采用醒目凸显的高对比强调色，在低饱和度的素雅底座中瞬间锁定视觉焦点，形成明确的主行动点。
- 功能状态色：精确定义成功、警告、危险和常规信息提示的标准语义色值，保持低调克制且语义清晰。

### 2. 排版与间距阶梯
- 字体层级：确立大标题、二级标题、正文、辅助说明与等宽代码字体的字号与行高基准，拒绝过度繁杂的字号规格。
- 呼吸留白间距：统一基于四像素或八像素网格建立标准间距阶梯，大板块之间严格预留充足的外边距留白。

### 3. 专业组件原子规范
- 基础组件规范：规范按钮、输入框、下拉框、卡片与弹窗的圆角大小、细边框样式与微阴影深度。
- 图标调用规范：列出组件库已引入的正式矢量图标名称映射，确保全站风格统一。

## 三、结合 PRD 梳理页面原型与上下流式布局

依据 PRD 中定义的用户核心流程，对涉及的全部页面进行骨架推演：

### 1. 视图布局骨架
- 严格遵循上下垂直推进骨架，通常划分为顶部沉浸式全局操作栏、核心主流程工作区、以及底部折叠辅助区或动作栏。
- 突出主流程单一焦点，次要功能通过合理留白收敛退后，避免同时出现多个抢夺视线的并列主体。

### 2. 响应式与跨端适配规则
- 明确断点策略，规范移动端与桌面端在不同屏幕宽度下的排版折叠策略与容器内边距动态收缩规则。

---

## 四、全状态交互契约设计

智能体必须为页面中所有关键交互元素补齐完整的状态呈现，坚决杜绝仅设计静态界面的残缺交付：

1. 默认常态：初始进入视图时的标准展示形式。
2. 悬停与聚焦态：鼠标划过与键盘聚焦时的微弱光影或边框强调反馈。
3. 加载进行态：发起异步操作、拉取数据时的骨架屏或局部轻量指示器，避免界面假死。
4. 空数据状态：列表或视图无任何数据时的克制说明文案与首项添加快捷入口，保证画面清爽。
5. 错误与异常态：接口调用失败、数据非法时的就地告警提示，清晰指引修复路径。

---

## 五、阶段完成标准与交付物

满足以下全部条件即视为完成本阶段：
1. 视觉系统规划完毕，严格排查并消除 Emoji 图标、副标题与说明文案、荧光外发光与元素堆砌。
2. 建立低饱和度中性基底，并在主要功能按钮上实现鲜明视觉凸显，主次层级分明。
3. 紧扣 PRD 业务需求，完成所有核心页面的上下流式原型推演与充足留白布局。
4. 关键交互元素完整覆盖常态、悬停、加载、空数据与异常等交互状态。
5. 核心设计系统与页面规范已完整写入项目根目录的 DESIGN.md 文件，并获得用户确认。
6. 实体原型必须归档落盘：生成的原型成果必须归档保存在 docs/stitch 目录中，作为后续前端编码实现的直观依据；生成手段可选用已配置的 Stitch MCP 服务或网页端手动导出，严禁将全量原型代码直接刷入会话导致上下文爆炸。

达成上述条件后，智能体输出设计系统概述，正式流转至阶段 05 前后端接口规范。

# 界面设计与用户体验规范

> 本文件为项目开发工作流的阶段 04 规范。智能体在 PRD 确认后必须执行本规范，依据业务功能与体验准则在项目根目录生成 DESIGN.md 实体设计方案。

---

## 一、阶段定位与界面设计核心红线

智能体在推演设计时，必须严格遵守以下硬性禁止红线，坚决剔除一切廉价的生成式页面质感：

1. 严禁使用绘文字充当图标：坚决禁止使用任何 Emoji 字符作为页面按钮、导航菜单或状态指示图标；必须严格选用项目既定组件库内置的矢量 Icon 组件，如 Lucide、Heroicons 或框架专用图标库。
2. 严禁标题附带任何副标题与说明文案：坚决禁止在标题下方添加任何形式的副标题、英文翻印或补充解释说明文字；模块标题必须干脆利落，功能边界完全依靠清晰的版面结构与控件自明，杜绝任何形式的文字打补丁与视觉噪音。
3. 严禁左右对称对半分栏：视图严禁采用刻板生硬的左右各占一半对半分栏布局，避免视觉割裂与呆滞感。
4. 强制采用自然上下流式布局：页面主体骨架必须采用清晰的主次自上而下递进布局，引导视觉重心单向自然流动。
5. 严禁页面元素堆砌，保证充足留白：坚决杜绝信息密不透风的视觉拥挤；必须通过大面积克制留白与合理行距拉开呼吸感，以空间间隔划分内容层级，而非依赖密集的边框与杂乱卡片。
6. 严禁使用荧光与外发光特效：坚决杜绝刺眼的荧光绿、荧光粉、霓虹发光色以及任何元素边缘外发光阴影特效，彻底摒弃劣质廉价的科技感渲染。
7. 严禁固定死板字号，强制流体排版：禁止依赖浏览器默认的 h1-h6 字号、预设固定标题字号类或组件内硬编码字号；保留 h1-h6 语义标题表达文档层级，其字号必须引用统一流体令牌。全站字体层级必须采用 clamp 函数实现响应式流体排版，兼顾视口变化与用户字体缩放。
8. 原型实体归档与防上下文膨胀原则：根目录的 DESIGN.md 与归档于 docs/stitch 目录下的原型文件同为本阶段的必须交付物；生成原型的手段则保持灵活，配置 Stitch MCP 服务为可选推荐方式，若未配置 MCP，可直接引导用户访问 https://stitch.withgoogle.com 生成后将原型产物存放至 docs/stitch 目录；同时坚决禁止将庞大的原型代码与冗余数据直接完整注入当前会话，严防智能体上下文过载。

## 二、设计系统基础资产与色彩规划

智能体在构建根目录 DESIGN.md 时，确立全局令牌体系：

### 1. 颜色体系与操作高亮规划
- 色彩基调：以素雅、沉稳、耐看的低饱和度中性色作为全站视觉底座。
- 饱和度控制：除核心警示与核心主操作外，全站优先选择饱和度较低、对比温和舒适的色彩，杜绝高饱和度大色块造成的视觉疲劳。
- 中性色阶梯：建立从深色正文文字、次级说明文字、浅灰细分割线到极浅背景底色的严密中性色带。
- 主要操作高亮突显：主要功能的操作按钮必须采用醒目凸显的高对比强调色，在低饱和度的素雅底座中瞬间锁定视觉焦点，形成明确的主行动点。
- 功能状态色：精确定义成功、警告、危险和常规信息提示的标准语义色值，保持低调克制且语义清晰。

### 2. 排版与间距阶梯
- 默认字体与回退：中文使用 Noto Sans SC；英文、拉丁字符及数字使用 Outfit，回退至 Segoe UI，最终使用 sans-serif。混排时按字符范围应用字体，避免中文字体中的拉丁字形抢占英文字体。
- 字体资产按需调用：为项目准备排版资产时，先检查 `references/Noto_Sans_SC,Outfit.zip`，仅选择性提取所需字体及字重，或选用对应可变字体；仅需 Outfit 时可用 `references/Outfit.zip`。避免整包解压，也不要将全部静态字重与可变字体同时引入。
- 字体加载与许可：将所需静态字重或可变字体及对应 `OFL.txt` 保存为项目本地独立资产，不将字体二进制嵌入 CSS；明确浏览器加载方式，不假定宿主机安装字体即可供浏览器使用，再分发时保留许可文件。
- 设计决策归档：生成项目的 `DESIGN.md` 必须写明中英文字体名称、回退顺序、资产来源、实际字体文件路径及字重、排版 CSS 入口路径与导入／引用方式。CSS 是可执行令牌的唯一来源，`DESIGN.md` 记录决策并引用实际 CSS，文档数值与实现保持同步。
- 流体字体层级：全站字号仅以统一 CSS 变量／设计令牌为来源；令牌采用已确认的具体数值 clamp 表达式，以 rem 定义最小值和最大值，理想值结合 rem 与视口单位，兼顾响应式缩放与用户字体缩放，不使用占位值。
- 排版与组件映射：生成项目的 `DESIGN.md` 必须包含排版令牌与组件映射表，覆盖项目实际使用的页面／区块／卡片标题、正文／辅助／错误文本、按钮／导航、表单标签／输入文本、表头／单元格及代码；逐项记录各角色令牌的最小值／理想值／最大值 clamp 表达式、字重与行高的实际数值，并将组件文字角色映射至令牌。同一语义角色跨组件复用同一令牌，不为各组件任意设置独立字号。
- 排版样式实体交付：遵循目标项目现有目录约定，在实际样式目录保存独立的 `typography.css`，包含指向所选本地字体文件的 `@font-face` 及实际字重范围／字重声明，以及可复用的 font-family、font-size、font-weight、line-height CSS 自定义属性和文字角色映射；由应用全局样式入口加载，组件统一引用其令牌，不以文字方案代替实际文件。
- 呼吸留白间距：统一基于四像素或八像素网格建立标准间距阶梯，大板块之间严格预留充足的外边距留白。

### 3. 专业组件原子规范
- 基础组件规范：规范按钮、输入框、下拉框、卡片与弹窗的圆角大小、细边框样式与微阴影深度。
- 图标调用规范：列出组件库已引入的正式矢量图标名称映射，确保全站风格统一。

## 三、结合 PRD 梳理页面原型与上下流式布局

依据 PRD 中定义的用户核心流程，对涉及的全部页面进行骨架推演：

### 1. 视图布局骨架
- 严格遵循上下垂直推进骨架，通常划分为顶部沉浸式全局操作栏、核心主流程工作区、以及底部折叠辅助区或动作栏。
- 突出主流程单一焦点，次要功能通过合理留白收敛退后，避免同时出现多个抢夺视线的并列主体。

### 2. 响应式与跨端适配规则
- 明确断点策略，规范移动端与桌面端在不同屏幕宽度下的排版折叠策略与容器内边距动态收缩规则。

---

## 四、全状态交互契约设计

智能体必须为页面中所有关键交互元素补齐完整的状态呈现，坚决杜绝仅设计静态界面的残缺交付：

1. 默认常态：初始进入视图时的标准展示形式。
2. 悬停与聚焦态：鼠标划过与键盘聚焦时的微弱光影或边框强调反馈。
3. 加载进行态：发起异步操作、拉取数据时的骨架屏或局部轻量指示器，避免界面假死。
4. 空数据状态：列表或视图无任何数据时的克制说明文案与首项添加快捷入口，保证画面清爽。
5. 错误与异常态：接口调用失败、数据非法时的就地告警提示，清晰指引修复路径。

---

## 五、阶段完成标准与交付物

满足以下全部条件即视为完成本阶段：
1. 视觉系统规划完毕，严格排查并消除 Emoji 图标、副标题与说明文案、固定死板字号、荧光外发光与元素堆砌。
2. 建立低饱和度中性基底，并在主要功能按钮上实现鲜明视觉凸显，主次层级分明。
3. 排版体系全面采用含具体数值、兼顾响应式与用户缩放的 clamp 流体字号；`typography.css`、所需字体及许可文件已实际保存，经应用全局样式入口接入，组件引用统一令牌；`DESIGN.md` 已记录字体资产、令牌数值、组件映射与 CSS 导入／引用方式，文档、CSS 与资产之间无路径或数值不一致。
4. 紧扣 PRD 业务需求，完成所有核心页面的上下流式原型推演与充足留白布局。
5. 关键交互元素完整覆盖常态、悬停、加载、空数据与异常等交互状态。
6. 核心设计系统与页面规范已完整写入项目根目录的 DESIGN.md 文件，并获得用户确认。
7. 实体原型必须归档落盘：生成的原型成果必须归档保存在 docs/stitch 目录中，作为后续前端编码实现的直观依据；生成手段可选用已配置的 Stitch MCP 服务或网页端手动导出，严禁将全量原型代码直接刷入会话导致上下文爆炸。

达成上述条件后，智能体输出设计系统概述，正式流转至阶段 05 前后端接口规范。
